# 单图 3D 生成「脸糊/脸崩」的业界方案调研

> 调研时间 2026-11-04。针对本项目现象：TRELLIS.2 原生纹理链生成的角色，
> 整体造型/服装还原很好，但五官糊、错位、被重绘，见 `out/face_compare_2cases.png`。

## 一句话结论

**有成熟方案，而且是成熟到已成共识的程度——但没有任何一个是「给 3D 生成器调个参数」就能解决的。**
业界的共同答案是：**把头部/人脸从通用 3D 生成里拆出来，用专门的人脸先验 +
可见区域直接取原图像素 + 局部增强**，最后再拼回身体。
对我们这种**二次元/风格化角色**，绝大多数现成方案（真人先验）并不直接适用，
最现实的仍是自己做「脸部高清贴图替换」。

---

## 一、我们的诊断就是业界公认的问题

上一轮我们算出：DINOv3 ViT-L/16 把 1024 输入压成 64×64 token，
全身图里脸只占 8×9 个格子。这不是猜的，多篇论文点名同一件事：

- **PSHuman**（arXiv:2409.10141）把 **"Face distortion"** 列为两大挑战之一：
  「the small size of the face in full-body images, which provides limited
  information for detailed normal prediction after VAE encoding」。
  解法是 **body-face cross-scale diffusion**：同时生成多视角全身图和局部脸部特写，
  用 noise blending 把脸部细节注入全局图。
- **SIGGRAPH Asia 2025**（DOI 10.1145/3757377.3763839）原文：
  「the face occupies only a small area in a full-body image
  (e.g., ∼80×80 pixels out of a 512×512 image). This limited resolution and
  **low weight for the facial regions during optimization** leads to insufficient
  facial details」。它把 **facial enhancement 直接集成进 3D 高斯优化**，
  再叠加超分 + 生成先验 + 多视角法线图。
- **SAMT**（ICML 2026）直接点名：「General-purpose 3D generators, such as
  **Trellis or Hunyuan3D**, often struggle to cross the uncanny valley …
  produce *melted* facial features」。
- **LHM**（ICCV 2025）用 **head feature pyramid encoding** 专门聚合头部多尺度特征。

所以结论很明确：**通用 3D 生成器对脸"不敏感"是结构性问题，不是配置问题**。

## 二、五条主流技术路线

| 路线 | 核心做法 | 代表工作 | 对我们的价值 |
|---|---|---|---|
| **A. 跨尺度 / 局部放大** | 全身视图与脸部特写**同时生成并混合**，脸部单独加权、超分 | PSHuman、SIGGRAPH Asia 2025、LHM | ★★★ 思路可直接借鉴（裁脸单独处理） |
| **B. 人脸专用先验** | FLAME/3DMM 拓扑初始化、Arc2Face 等**人脸基础模型**做 ID guidance、面部区冻结致密化 | Arc2Avatar (CVPR 2025)、Pixel3DMM、PSHead | ★ 仅限真人，二次元失效 |
| **C. 多视角扩散 → 前馈重建** | 先生成身份一致的侧/背视图，再重建 3D；用**剪影对齐**消 ghosting | FaceLift (ICCV 2025)、SAMT、AAAI 2026 ID-TS | ★★ 官方已有 `Projection_*_Qwen_*Views.json` 可走 |
| **D. 可见区直取 + 不可见区补全** | 弱透视投影**从原图直接抠脸部纹理像素**，柱面 UV 参数化，遮挡区标灰交给扩散 inpaint | **GD-Head** (ICMR 2026) | ★★★★ **最贴合我们的需求**，且不需要训练 |
| **E. GAN 反演 / 伪监督补后脑** | PanoHead 潜空间反演 + Wonder3D 生成后脑伪标签 | PanoHead、PSO-HEAD、Dual Encoder (NeurIPS 2024) | ★ 只解决后脑，不解决正面五官 |

> **路线 D 就是我们上一轮推荐的「脸部高清贴图替换」的学术版**：
> 不重绘可见的脸，只补看不见的部分。这是唯一能**绕开 DINO token 上限**的思路，
> 因为原图像素根本没经过 DINO。

## 三、可落地开源工具（按「脸部细节优先」）

| 工具 | 定位 | 许可 | 硬件 / 限制 |
|---|---|---|---|
| **PSHuman** `pengHTYX/PSHuman` | 单图全身 → 带纹理网格，跨尺度 body-face 扩散，约 1 分钟 | MIT | **768 模型需 40GB+ 显存**，本机 24GB 不够；512 版在计划中 |
| **SOAP** `TingtingLiao/soap` | **Style-Omniscient**，明确支持照片/**卡通**，输出 FLAME 拓扑 + UV、带眼球牙齿、可表情驱动 | SIGGRAPH 2025，代码+数据已放出，研究用途 | 依赖 face-alignment / MediaPipe / EMOCA / nvdiffrast；**是所有方案里最贴二次元的** |
| **LAM** `aigc3d/LAM` | 单图 → 可驱动高斯头，1.4s，FLAME 初始化 + 两次细分到 81k 点 | **Apache-2.0**（权重另有 LICENSE_WEIGHT） | 输出是高斯头不是网格；large 权重未放出 |
| **Arc2Avatar** | Arc2Face 作 SDS guidance，面部区禁用 densify/prune | 训练代码+模型 2025-06 放出 | 逐例优化，4090 测过；真人向 |
| **FaceLift** | 合成数据训练、真实图泛化的 360° 高斯头 | 代码 Apache-2.0，**权重 Adobe Research License 禁商用** | 真人向 |
| **GD-Head** | 3D 纹理重建 = 2D inpainting（路线 D） | 论文原文是 *will be made publicly available*（将来时），**撰写时尚无代码**，只能借鉴方法 | 工程实现最小，真人向但方法通用 |
| **Pixel3DMM** | DINO 主干预测法线/UV → FLAME 拟合，几何精度 +15% | 项目页公开 | 只解决几何，不解决贴图 |

> 上述 6 个 GitHub 仓库（`muyuWang/SAMT`、`TingtingLiao/soap`、`aigc3d/LAM`、
> `pengHTYX/PSHuman`、`Tencent-Hunyuan/Hunyuan3D-2.1`、`weijielyu/FaceLift`）
> 均于 2026-11-04 通过 GitHub API 核实存在；但「仓库存在」≠「权重/代码完整可跑」，
> 落地前仍需逐个看 release 与 license。

**Hunyuan3D 2.1**（`Tencent-Hunyuan/Hunyuan3D-2.1`，开源权重）值得单独提：
它的纹理管线用 **custom_rasterizer 多视角渲染 + Real-ESRGAN 4× 纹理超分**，
是「生成后对贴图做超分」的现成工业实现，可借鉴。
注意仓库里的 `FaceReducer` **不是人脸增强**，是把网格简化到 40K 面的组件，别看名字误读。
另外 Hunyuan3D 2.1 全套 shape+paint 需 29GB 显存（分阶段跑各 10/21GB），
3.0 宣称「针对人物专项优化、精细面部重塑」但为闭源 API。

## 五、最关键的一条判断：真人先验对我们基本失效

上面几乎所有方案都建立在**真人**假设上：

- FLAME / SMPL-X 头骨拓扑、3DMM 参数模型 → 二次元大眼、小鼻、无下颌角不在流形内；
- ArcFace / 人脸 embedding 做身份约束 → 对卡通脸没有判别力；
- face-alignment / MediaPipe landmark、face parsing → 动漫脸常检测失败；
- 皮肤纹理超分（Real-ESRGAN / GFPGAN 类）→ 会把赛璐璐的干净色块锐化出噪点和伪纹理；
- 训练数据（FaceScape / NPHM / Ava256 / RenderMe-360）全是真人扫描。

**例外**：SOAP 名字就是 Style-Omniscient，明确面向照片与卡通；
以及**路线 D（GD-Head 式直取原图像素）根本不需要人脸先验**，
对二次元同样成立——因为它是「搬运像素」而不是「理解人脸」。

这解释了我们的实测：赛璐璐骑士（大色块硬线条）生成得干净，
写实细密五官的汉服崩掉。**决定结果的是信息频率，不是像素分辨率。**

## 六、对 meow3d 的落地建议（按性价比）

1. **脸部高清贴图替换（推荐先做）**
   从原图裁高清脸 → 用生成时的正面相机把脸部三角面投影到 UV 图集 →
   直接写入原图像素 → 边缘羽化融合 → 重新打包 GLB。
   零训练、适配二次元、绕开 DINO、不动几何。对应 GD-Head 第一步 +
   Headshot 3 的 Blend Mask 思路。
2. **脸部图块单独超分/重绘**
   对 UV 图集里头部图块用高分辨率模型重绘（可复用主项目 Qwen-Image-Edit），
   或纹理超分。借鉴 Hunyuan3D 2.1 的 Real-ESRGAN 4×；
   但对赛璐璐要关掉过锐，优先「重绘」而非「超分」。
3. **多视角 + 剪影对齐**
   官方已有 `Projection_Hy20_Qwen_4Views.json` / `Projection_NvDiffrast_Qwen_XViews.json`，
   用 Qwen 生成侧/背视图再投影。关键是学 SAMT 的 **Powell 剪影对齐**，
   否则多视角融合会出 ghosting，比单视角更糟。
4. **头部专用分支拼接（重）**
   用 SOAP 单独出一个风格化头，再与 TRELLIS.2 身体合并。
   工作量最大、要处理拓扑/材质/接缝，但这是业界"根治"的做法。
5. **换生成器**：Hunyuan3D 3.0 宣称人脸专项优化，但闭源 API + 真人向，
   且本项目已经把 TRELLIS.2 链路打通，不划算。

## 七、许可与风险

- 本项目底模是 Qwen **RESEARCH LICENSE**（非商用），所以现阶段用
  FaceLift / SOAP 这类研究授权方案不会额外收紧约束；**但未来商用要一并换掉**。
- PSHuman 的 40GB+ 显存是官方 README 明示门槛，本机 4090 24GB 跑不了 768 版。
- 论文里的速度（LAM 1.4s / PSHuman 1 分钟 / HRAvatar 155 FPS）均为作者自测，非独立复现。
- 人脸/肖像重建涉及生物特征与肖像权；本项目用 CC0 素材测试，不涉真人肖像。
