# 投影贴图管线（projection-based texturing）

> ⚠️ **2026-11-04 复研修正**：本文下面 `--mode blend/qwen` 的「UV texel 空间投影」

> **Cycles 材质层 / 3D 表面点**做投影、最后 bake 到重新展开的干净 UV。
> 详见 `docs/StableGen复研-投影作用域.md`。
> **`replace` 模式不受影响，仍可用。**

> + bake），bake 出来不再碎，效果优于本文的 `replace`。

## 为什么做

两条理由指向同一件事：

1. **画质**：单图 3D 的脸糊，根因是 DINO 把脸压成 8×9 个 token；
   唯一能绕开它的是「原图像素直取」而不是「重绘」。
2. **商用**：现有原生纹理链用到 nvdiffrast / nvdiffrec（NVIDIA 非商用许可）；
   projection-based 纹理模式完全不用它们。

## 代码结构

```
meow3d/projection/
  geometry.py   UV 空间映射 / 环绕相机 / 可见度权重 / DPPG
  views.py      ViewProvider（正面原图直贴、几何重投影、扩散模型接口桩）
  pipeline.py   混合 / UV 补洞 / 导出 GLB / Reproject 缓存
tools/project_texture.py   命令行
tools/uv_unwrap.py         给无 UV 白模展开 UV（Blender Smart UV Project）
tests/test_projection.py   6 条纯逻辑单测
```

### 六个要素怎么落的

| 要素 | 实现 |
|---|---|
| 多相机 | `make_cameras`：方位角均匀、仰角 ±12° 交替，默认 8 个（2–32），第 0 个固定正面 -Y |
| `cos^k` 可见度加权 | `visibility_weights`，默认 k=3，Discard angle 90°，可 `--exponent` / `--discard` 调 |
| DPPG 深度边界抑制 | 深度场 Sobel 梯度 → 只取最强的 ~2% 边界 → dilate + Gaussian 羽化 → 压低该相机权重（0.6 强度）；抑制过头有 `coverage rescue` 用无 DPPG 权重补 |
| 正视图上下文 | `HybridViewProvider`：正面相机直接搬**原图像素**；原图透明处用底图打底，避免留黑 |
| UV 补洞 | `_fill_holes`：优先用底图颜色，没有底图才 `cv2.inpaint`（TELEA） |
| Reproject 缓存 | UV 映射 `*_uv{S}.npz` + 每相机视图 `*_views{S}/*.npy`；`--reproject` 时只重算权重与混合 |

**核心取舍**：不在相机图像空间光栅化，而是在 **UV 图集空间**做一次反向映射
（每个 texel 属于哪个面、对应哪个 3D 点与法线）。这份映射最贵，缓存后
改混合参数只需毫秒级重算 —— 这正是 StableGen 的 Reproject。

## 两种模式

```bash
# 默认：保守替换。正面原图像素直贴，其余 texel 原样保留底图
python tools/project_texture.py 带UV的.glb 原图.png --out out/xxx.glb

# 完整多相机混合（实验性）
python tools/project_texture.py 带UV的.glb 原图.png --out out/xxx.glb --mode blend

# Reproject：改权重指数，复用缓存视图，不重新生成
python tools/project_texture.py 带UV的.glb 原图.png --out out/xxx2.glb \
    --exponent 8 --reproject
```

**为什么默认不是 blend**：StableGen 的投影价值来自 SDXL / Qwen 为每个视角
**生成新信息**。没有 2D 生成模型时，「把 UV 图集重投影成侧背视图」信息量不增反减，
且 xatlas 的 UV 图集是 106 个碎片岛，重投影会把碎片搬错位置 —— 实测 blend 模式
产出满屏碎玻璃。因此默认走 GD-Head / Headshot 3 那套更稳的做法：
**可见区直取原图像素，不可见区保持原样**。blend 保留为接生成模型后的实验入口。

`DiffusionViewProvider` 是接口桩：接 Qwen-Image-Edit / SDXL（用 Depth/Normal
渲染图当结构参考、已贴纹理当上下文）时只改 `views.py`，其余模块不用动。

## 实测（CC0 骑士，46 万面，1024² 图集）

| 项 | 结果 |
|---|---|
| UV 映射（首次，含 19 万微小面中心近似） | 覆盖 55.9% texel（xatlas 图集利用率本就低），约 20s，之后命中缓存 |
| `replace` 模式 | 替换 27.3% 有面 texel（正面可见区），**1.9s** |
| `blend` 模式 | 8 相机各贡献 21–31%，有面 texel 覆盖 95.7%，4.5s |
| Reproject `--exponent 8` | 复用视图，3.4s，覆盖率随 k 增大降到 75.1%（符合预期，证明参数生效） |
| 单测 | `pytest tests/test_projection.py -q` → 6 passed |

**效果**：`out/projection_vs_native.png` 对比。replace 模式正面白披风、
蓝纹章、金边、面甲都明显更锐利（原图像素），侧背保持干净；
blend 模式在无生成模型时退化成碎片，已如实记录。

## 踩过的坑（都是「不报错但结果错」）

1. **深度方向反了**：`depth = dot(P-center, camera_dir)` 越大越靠近相机，
   一开始按 `min` 判可见 → 把背面当正面 → 贴图整片错乱。
2. **硬遮挡阈值把 99% 表面判死**：屏幕格里只保留最近一个 texel，覆盖率 2.3%。
   改成软可见度 `exp(-gap/thickness)`，覆盖率 95.3%。
3. **DPPG 把 UV 岛边界当深度边界**：UV 图集岛与岛之间本来就有跳变，
   全图 Sobel 会把 53.7% texel 压掉。改成只在岛内部（erode 后的 inner 区）
   取梯度分位数，只压最强约 2%。
4. **原图透明处留黑**：正面 view 的 alpha=0 区域若填 0，会把黑色涂到模型。
   改成用底图颜色打底，并把该区域仍标记为有效视图。
5. **统计口径**：UV 图集利用率低是 xatlas 的正常现象，覆盖率应该按
   「有面的 texel」算，不是全图。

## 接入主项目 Qwen-Image-2.1 的对照实测（2026-11-04）

**约束**：主项目 `2d-game-meow` 严格只读、还要继续用；权重用硬链接。

### 怎么做到零改动

- `tools/link_qwen.py`：把 `checkpoints/qwen-image-2.1`（35 文件 / 51G）、
  `lora/`（Lightning + AnyAngle）、`controlnet/qwen21_union.safetensors`
  以 `os.link(src, dst)` 接到 `meow3d/models/qwen/`。**44 文件、0 复制**，
  同卷不占额外空间；源 inode link count 1→2，文件内容/mtime 不变。
- `tools/qwen_views.py` **用主项目 venv**（py3.13 / torch2.6 / diffusers0.41）跑，
  只读 `import workflows.engine.Engine`（该模块只依赖 torch，`workflows/__init__.py` 为空）。
  命令行强制 `PYTHONDONTWRITEBYTECODE=1`、cwd 始终在 meow3d、所有产物写 meow3d。
- 验证：主项目 21:00 后**无任何新 pyc**、`git status` 干净、抽样源文件 mtime 未变。
  Engine 的 `models_root` 传绝对路径指向硬链接目录，完全绕开主项目 assets。

### Qwen 出图

`QwenImage21Pipeline` 一个管线同时支持文生图与**指令改图**（传 `image` 即编辑），
挂 `qwen21_lightning` LoRA 跑 8 步。640² 实测 **3–4 s/张**，管线加载 12–15 s。
生成 4 个正交视角（`--indices 0,2,4,6`）：

| 视角 | 结果 |
|---|---|
| 正面 0° / 背面 180° / 左侧 270° | 好：身份、银蓝铠甲、白披风、蓝纹章、羽饰一致，T-pose 保持 |
| **右侧 90°** | **没转过来，仍偏正面** —— 单靠提示词做角度的老毛病；需 `qwen21_anyangle` LoRA 或 ControlNet Union depth 引导 |

> 跑 8 视角那次曾出现第一张卡 8 分钟、GPU 24G 满载（显存压线反复重试），
> 换成 4 视角 + 640² 后恢复正常。这个不稳定性要记着。

### 三方对比（`out/three_way_compare.png`）

| | 结果 |
|---|---|
| ① 原生纹理链 Native | 干净但脸糊 |
| ② **投影 `replace`（正面原图直贴）** | **最干净、最锐利** |
| ③ 投影 `qwen`（Qwen 4 视角完整混合） | **碎玻璃** |

**关键诊断**：`--mode qwen` 用 `QwenViewProvider` 把 Qwen 新视角喂进完整混合，
覆盖率 76.5%，结果仍碎；再跑 **单相机对照**（只用 cam0 + Qwen 正面图）**也碎**。
→ 所以瓶颈**不是多相机加权、也不是缺新视角信息**，而是
**「逐 texel 按 `cam.screen()` 坐标采样视图」在 xatlas 的 106 个碎片 UV 岛
+ 1024² 图集上不成立**：UV 映射只覆盖 55.9% texel，19 万微小面只写了中心像素，
`uvm.points` 在岛之间跳变，相邻 texel 采到视图里完全不同位置的颜色。

**结论（诚实）**：Qwen 本身出图质量很好，值得继续用；但当前投影混合器
配不上它。要真正吃下多视角，得把采样单位从「texel」改成「三角面」
（逐面投影 + 重心插值），或直接用 Blender bake；顺带把 atlas 提到 4096。
**在此之前，最稳的仍是 `replace` 模式。**

## 商用路径的剩余缺口（重要，别当成已完成）

当前验证用的输入是**已有 UV 的带纹理 GLB**（UV 与底图来自原生纹理链产物）。
要做出完全独立于 NVIDIA 库、可交付的链路，还差：

1. ✅ `MeshOnly.json` 工作流只出白模（不含 `MeshTexturing`，因此不用
   nvdiffrast/nvdiffrec）—— `tools/generate.py --workflow ... --plan` 已验证
   18 个节点全部可映射。
2. ✅ `tools/uv_unwrap.py` 给白模展开 UV（Blender Smart UV Project，
   可选 `--decimate` 先降面，否则几十万面会很慢）。
3. ⬜ **侧背贴图来源**：从白模出发没有底图，replace 模式只有正面有颜色。
   必须接 `DiffusionViewProvider`（Qwen-Image-Edit / SDXL + depth guidance）
   生成多视角，或走官方 `Projection_*_Qwen_*Views.json` 工作流。
   这一步做完，才是不依赖 NVIDIA 库、也不依赖原生链产物的完整商用链。
