# 路线一样，为什么效果比不上 StableGen（2026-11-05 逐项定位）

> 对照源码：`D:\code\gen\others\StableGen-main`（v0.4.x，约 3 万行）
> 本文只列**代码证据**，不猜。每条都带文件名 + 行号。
> 本轮已落地的改动与实测数字见文末第七节。

## 结论先行

**「多视图扩散 → 投影 → bake」这条路线名相同，但 Qwen 输出在管线里的角色
完全不同：StableGen 把它当「补丁」，meow3d 把它当「整张替换」。**

再叠加三个放大器：起点不同（白模 vs 已带贴图）、采样配置不同（20 步无蒸馏
vs 8 步 Lightning）、相机/权重/闭环的工程完整度差一个数量级。
所以差距不是「调参没调好」，是**语义层级就走岔了**。

---

## 一、最致命：补丁 vs 整幅替换

StableGen 的 `sequential` 不是「每个机位独立出一张新贴图」：

```python
# stablegen/texturing/generator.py:1874-1880
elif context.scene.generation_method == 'sequential' and self._current_image > 0:
    render_info = ... "inpaint", subtype="render"     # 当前已投影纹理的渲染
    mask_info   = ... "inpaint", subtype="visibility" # 可见性/未覆盖 mask

# :1955-1975  每个后续机位先渲 context + visibility，再生成
yield from export_visibility(context, ..., camera_render=_cur_cam, ...)
yield from export_emit_image(context, ..., fallback_color=fallback_color, ...)
```

提示词把这件事写死在模型约束里：

```python
# stablegen/texturing/workflows.py:928-945  QWEN_21_DEFAULT
"Edit image 2 into '{main_prompt}'. Preserve its existing "
"non-magenta textured regions. Replace every solid magenta "
"region with texture that seamlessly continues the surrounding "
"surface. Use image 1 only as a geometry and composition guide."
```

而且有四道护栏**从工程上保证已贴好的像素不被改写**：
`_apply_qwen_binary_context_mask` (`generator.py:520`)、
`_dilate_qwen_context_fallback` (`:667`)、
`_apply_qwen_context_cleanup` (`:711`)、
`_reject_qwen_fallback_writes` (`:626`)。

meow3d 旧路径（`tools/run_guided.py` 改写前）是四个机位**各自整幅重绘**，
再用 `bake_projection.py` 把整张图铺进 UV 图集。已正确的原生贴图被全盘覆盖，
8 步 Lightning 的画风漂移 100% 继承 —— 用户自己的实测（`out/asuka_style_test.png`）
已经写明：橙发变浅金、正红战服变亮、赛璐璐变半写实、边缘发软。

## 二、起点不同：白模 vs 已带贴图

| | StableGen | meow3d（旧） |
|---|---|---|
| 输入网格 | TRELLIS.2 白模，**没有贴图** | `asuka_Textured_00001_.glb`，**自带完整贴图** |
| Qwen 的角色 | 唯一颜色来源 | 把已经对的贴图再「发明」一遍 |
| 因此 | 重绘是必需 | 重绘是**净损失** |

`docs/与StableGen的差距-实测定位.md` 第二节已量出这一步是负收益，但没把
「起点不同」这层说透。同一套代码搬到一个已经贴好图的网格上，语义就反了。

## 三、生成模型与采样参数（几乎每一项都不同）

| 项 | StableGen `QWEN 2.1 PRECISE` | meow3d 旧默认 |
|---|---|---|
| 模型调用 | `TextEncodeQwenImageEditPlus`，`image1/2/3` 三个语义槽 | `Engine.txt2img_pipe()` 传一张 `image` |
| 输入图 | **3 张**：几何引导 / 已投影上下文（品红 mask）/ 整体外观参考 | **1 张**（beauty），`--reference` 实际未使用 |
| steps | **20** | **8** |
| cfg | 1.0 | 1.0 |
| sampler | `dpmpp_sde` + `sgm_uniform` | 默认 Euler / simple |
| Lightning LoRA | **无** | `qwen21_lightning`，并强制 `steps=min(steps,8)` |
| 输出 | **native RGBA**，透明像素排除投影 | 浅灰底 + BiRefNet 事后抠图 |
| 权重指数 | 7.0（预设）/ 成品 15.0 | 3.0（CLI 默认），run_guided 8.0 |

证据：
- `stablegen/ui/presets.py:88-110` —— 20 步 / CFG1 / DPM++ SDE / SGM Uniform / `lora_units: []` / `qwen_image_21_native_rgba: True`；描述里直写「produced broad, coherent panels that followed the model silhouette」。
- `stablegen/util/workflow_templates.py:1285-1300` —— Qwen Edit 模板。
- `stablegen/texturing/workflows.py:189, 611-631` —— `image1/image2/image3` 槽位装配。
- `meow3d/tools/qwen_guided_views.py:166-175` —— 挂 Lightning 且把步数夹到 8。
- `meow3d/tools/qwen_guided_views.py:216-227` —— **`--ref` 空转**：单图模式下
  `imgs = []` 后只 append beauty，`ref_sq` 仅在 `if not imgs` 兜底分支用到。
  也就是说 run_guided 一直传 `--reference`，但它**根本没进模型**。

> 主项目 `2d-game-meow/workflows/engine.py:740-750` 自己的实测也写着：
> 「8~12 步浅色主体对比度不够、细节发白，16 步起才稳定」。
> 8 步蒸馏用于 32~128px 精灵图是够的，用于 3D 贴图是明显欠采样。

## 四、相机布置

| | StableGen | meow3d |
|---|---|---|
| 数量 | 默认 **8**（2–32） | 固定 **4** |
| 放置 | `normal_weighted`（面法线面积加权 K-means）/ `greedy_coverage`（覆盖率目标 0.95，BVH 验证可见性） | 方位角等分 `i*360/N` |
| 俯仰 | 有 elevation，且可 clamp 避免极端顶/底视 | `elevation = 0.0` 全水平 |
| 画幅 | Auto Aspect Ratio / Fit camera resolution，按轮廓自适应 | 固定 `ORTHO=2.8`，角色仅占约 73% 画幅 |

证据：`stablegen/core/properties.py:1048-1062, 1106-1142`；
`stablegen/cameras/placement.py:59-85, 524-635`；
`meow3d/meow3d/projection/guidance.py:camera_list`、`bake.py:ORTHO=2.8`。

4 个水平环绕相机覆盖不到头顶、肩窝、腋下、脚底；局部细节被 1024² 视图
压到 ~90px 头部，再投进 2048² 图集要放大 6~8 倍 —— 这是「糊」的直接来源。

## 五、投影混合与遮挡

StableGen 在 **3D 表面逐点**算，不是 UV texel 反向采样：

```osl
// stablegen/raycast.osl:56-75
if (trace(Origin, d)) {                       // 真光线遮挡
    getmessage("trace", "hitdist", Distance);
    if ((Distance + RayEpsilon) < threshold) Result = 0;
    else {
        float orthogonality = max(-dot(d, normalize(SurfaceNormal)), 0);
        if (angle > AngleThreshold) Result = 0;
        else Result = pow(orthogonality, Power);
    }
}
```
配 `feather.osl:58-62` 视锥边缘平滑、DPPG 3px 边界带 + 12px 羽化
（`sg_silhouette_margin`、`sg_silhouette_feather`）、AQW 采集质量加权
（`texturing/confidence.py`）、CGC 置信度门控、逐像素 max 归一化、
`util/color_match.py` 多视图接缝配色，且**生成期 discard 50° / 成品 90° 分两阶段**
（`presets.py:169-181`）。

meow3d：Z-pass 深度图近似遮挡 + `max(dot(N,-cam_dir),0)^k` + alpha
（`tools/blender_bake_views.py:158-215`）。没有 raycast、DPPG、边缘羽化、
AQW、CGC、颜色匹配，也没有分阶段 discard。

---

## 六、闭环/迭代能力

StableGen 有 `Reproject`、`Masked Edit`、`Local Edit`、`UV Inpaint Missing Areas`、
`refine_images`、PBR 分解，可以反复局部修；meow3d 的 `--reproject` 只能改
混合参数重算，不能增量修某一块。

| 改动 | 文件 |

| 新增保护性精修：YUV 颜色锚定 + 局部清晰度门控 + 受保护合成 | `meow3d/projection/refine.py`（新） |

| 编排改为 5 步；默认 **20 步 / 无 Lightning**；暴露 `--protect`、`--anchor`、`--two-images` | `tools/run_guided.py` |
| 7 条新单测 | `tests/test_refine.py`（新） |

**关键修正**：一开始拿 `beauty`（带灯光）当颜色基准，贴图被写上「已经打过光
的颜色」，渲染时二次打光，实测几乎没改善。换成 `flat` 后才有质变 ——
这正是 StableGen `export_emit_image` 用 Emission 渲上下文的原因。

### 实测数字（Asuka，RTX 4090，同一张 GLB / 同一组 4 视图）

| 指标 | 旧 guided（整幅重绘） | beauty 基准 | **flat 基准（新）** |
|---|---|---|---|
| 贴图相对原生平均 \|ΔRGB\|（覆盖区 81%） | 0.1755 | 0.1670 | **0.0816** |
| 同一指标 p90 | 0.3765 | 0.3451 | **0.2000** |
| 覆盖区均值 RGB | [0.552,0.313,0.225] | [0.724,0.413,0.292] | **[0.644,0.276,0.109]** |
| 原生参考均值 | — | — | [0.668,0.300,0.121] |

平均色偏 **-53.5%**、p90 **-46.9%**，颜色均值基本回到原生。
`--protect 0.85` 时平均只改写 **22%** 的前景像素（78% 保留底图），
精修 4 张 **2.7s**、`--align frame` bake **17.5s**、端到端编排 **20.2s**，
覆盖率 80.4%，GLB 21.6MB（二进制换贴图，网格字节未改）。
全量单测 **40 passed / 1.2s**（改前 33 passed）。

### 20 步 vs 8 步（同输入、同机位 v00、1024² 单张实跑）

| 指标 | 8 步 Lightning（旧默认） | **20 步无 LoRA（新默认）** |
|---|---|---|
| 与 flat 基准平均 \|ΔRGB\| | 0.2264 | **0.1681（-25.7%）** |
| 前景高频能量 | 0.0327 | 0.0246（flat 自身 0.0264） |
| 单张耗时 | ~4s | **22.0s**（管线加载另 23.3s） |

8 步版把角色画成偏暗的半写实、脸型漂移；20 步版发色/战服红/五官明显更
贴近 flat。4 视图全程约 **2 分钟**，成本可接受，已设为默认。
对照图 `out/qwen_steps_compare.png`。

对比图：`out/asuka_refine_compare.png`（视图级三联）、
`out/asuka_guided_views.png` vs `out/asuka_refined_flat_views.png`（3D 四视角）。

## 八、还没做，按性价比排序

1. **20 步无 Lightning 的完整 4 视图 A/B**：单张已验证（见上），但还没跑完整
   4 视图 bake 出最终 GLB 再与 8 步版对照。预期锐度再补一档、约 2 分钟。
2. **相机 8 + normal-weighted 放置 + elevation**：`camera_list()` 目前写死等分
   水平环，改成可吃方向列表即可，收益在头顶/腋下/脚底覆盖。
3. **裁满画幅**：把角色裁到占满 1024² 再喂 Qwen（当前约 73%），头部有效
   像素白拿 ~1.36 倍；注意同步改 `projection_bbox` 的对齐基准。
4. **DPPG / 视锥边缘羽化 / AQW**：在 `blender_bake_views.py` 的权重节点图里
   加深度跳变 3px 抑制与 `edge = max(|x_c|,|y_c|)` 羽化。
5. **白模路线**：从 `MeshOnly` 白模出发时设 `--protect 0`，并把参考图作为
   `image3` 外观锚注入（StableGen `QWEN 2.1 CONTEXT + REFERENCE` 的形态）。
   这条要小心双图拼图问题，先小范围验证。
6. **多视图颜色匹配到 UV 接缝**：移植 `util/color_match.py` 的思路自己实现，
   消除相邻机位色差。
7. **native RGBA**：Qwen 2.1 预设支持，可省掉 BiRefNet 抠图及其边缘误差。
